IMU ingestion and timing review
Review date: 2026-10-12. Local dev changes; not committed, pushed or merged.

Implemented
- SequenceImu loads each side once per trajectory. load_sample optionally attaches
  both sides' timestamp brackets; default sensor loading does not open IMU files.
- Strict ordering stays the default. Explicit sorting uses copies and logs the
  three backward intervals across six streams. All raw IMU hashes are unchanged.
- Duplicate timestamps are rejected, including non-adjacent duplicates in the
  manifest builder. Reports cannot be written inside the raw dataset root.
- Every IMU query requires an explicit gap tolerance. Out-of-span or excessive-gap
  brackets return valid=False, -1 indices and NaN measurements, with a reason.
- Original measurement columns are retained unchanged. No vector interpolation,
  clock correction or assumed accelerometer/gyroscope axes were introduced.
- IMU reader reuse rejects changed roots, trajectories, side paths and escaping
  paths. Returned arrays/reports do not mutate cached observations.

Verified
- 29 contract tests passed, including 10 new IMU integration/regression tests.
- All 3,088 frames / 6,176 frame-side timestamp queries reviewed; nine native
  beginning/middle/end samples decoded with IMU attached.
- Full both-camera image/LiDAR audit passed: 21,616 payloads, zero errors.
- Rebuilt manifest is byte-identical; dates, splits and frame records unchanged.
- Code compiles; formatting and Git whitespace checks pass.
