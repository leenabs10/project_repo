DubaiDATA MVP capability and readiness assessment

Product direction
A customer-adaptable synthetic-data pipeline built around a dataset-independent core,
simulator-independent generation contracts and infrastructure-independent execution.
TorWIC warehouse data is the reference integration; goods segmentation is the primary
benchmark. The architecture describes the intended reusable boundaries, not a claim
that every adapter, backend or execution environment is implemented.

Verified data foundation
- All 3088 trajectory frames and 21616 sensor payloads passed ingestion checks.
- Complete-trajectory membership is preserved: 1136 training, 1037 development
  validation and 915 held-out test frames. No model evaluation on the test set is claimed.
- Training characterization covered 1136 frames and 7952 payloads.
- All four depth caches match manifest membership and raw-source derivatives:
  4346 native RGB/depth files and 4346 cached frame derivatives verified.
- Legacy 160x90 RGB uses BILINEAR; 320x180 RGB uses BOX. Depth uses NEAREST,
  stores uint16 millimetres and converts to metres. Invalid zero depth is excluded
  from supervision. These are reference-adapter conventions, not universal constants.
- IMU ordering/bracketing protection is implemented. Coverage remains partial in
  development/held-out data; measurement-column units/frame binding remain unresolved.

Verified generation and research evidence
- A three-scenario Blender pilot exports native RGB, metric axial depth, semantic
  and binary goods masks, camera poses, generation settings and lossless packages.
- An analytic fixture verifies axial depth; 768 interior rays passed class agreement
  and geometric checks. Boundary alignment and natural appearance require separate qualification.
- Native paired augmentation accepted 25 variants and rejected 11 with explicit
  integrity rules. This establishes derivative integrity, not calibrated sensor realism.
- Seven nearest-fill scenarios reproduced their measured-depth validation baselines.
- 5185 scenario/frame mask checks and 3111 training-only donor queries passed.
- Four training RGB/depth/mask pairs were visually inspected. Unknown-depth predictions
  remain estimates without independent reference values.
- The engineering contract suite passed 115 tests. Depth research is separate
  from goods-segmentation performance and does not demonstrate synthetic-data utility.

Architecture and integration readiness
Verified components include TorWIC-specific ingestion/profiling, depth research and
the custom Blender pilot. Canonical sample/cache-job contracts, TorWIC and declared
paired-PNG adapters, shared cache preparation, local storage and a separate-process
executor are verified. The installed host CLI and built-wheel schema loading passed.
Shared scene workers and remote execution/storage remain integration work. BlenderProc tools are prepared;
end-to-end renderer compatibility and acceptance require a validated integration.
Isaac Sim and cloud execution remain conditional extensions rather than commitments.

Required quality evidence
- Independent goods-reference masks and approved taxonomy/uncertainty rules.
  Existing trajectory semantic masks are model predictions with identified errors.
- Appearance and mask-boundary qualification before synthetic samples enter training.
- Complete controlled RGB/depth/LiDAR conditions with parameters, clean references,
  measured condition/coverage results and documented sensor-realism limits.
- Extra annotated pairs: all 237 remain quarantined until provenance and overlap
  with held-out data are resolved. Their indexed masks require per-file label mapping.
- Real exported-image distortion/registration conventions and IMU vector meaning
  remain source-evidence requirements. Optional fusion stays disabled.
- Dedicated simulated LiDAR is unavailable. Camera-depth unprojection is not a
  LiDAR scan; the full same-scene RGB/depth/LiDAR generation gate remains open.
- Matched real-only versus real-plus-synthetic goods experiments and independent
  locked-real evaluation have not established model improvement.

Acceptance and delivery
Keep integrity, geometry, requested conditions, fidelity, coverage, reference-label accuracy
and task utility as separate gates. Unsupported capabilities must remain explicit.
Deliver traceable accepted samples, configuration, quality/coverage evidence and
honest benchmark results. Proposed targets are not guaranteed gains or safety claims.

Adapter preparation verification
The full 2173-frame training/development RGB/depth rebuild matches the existing research caches
byte-for-byte, including complete NPZ hashes. Provenance entries match source hashes.
Native multimodal loader parity passed on two representative samples. Core tests
exercise different dimensions, centimetre depth units and a different invalid sentinel.
No source data, old caches or protected checkpoints were modified. Pixel processing
uses disk-backed arrays/chunked verification; production-scale performance is unproven.
See docs/tech_stack.txt and docs/adapter_foundation.json for interfaces and evidence.

Controlled real-sample synthesis verification
Portable preserve/vary/prohibit controls now drive native RGB gain and training-only
depth-mask transfer through the same local executor. All 18 requested variants are
accounted for: 11 passed automated checks, 7 were rejected. Brighter images exceeded
the clipping envelope in three cases; depth-mask transfers failed coverage/dropout
limits in four. Rejections and missing condition coverage remain visible.
Clean references, LiDAR and semantic files are byte-identical. All retained depth
measurements and exported validity/hidden masks passed checks. A repeated run produced
identical data, diagnostic artifacts and acceptance decisions. No validation/test sensor payloads were read.
Appearance qualification and independent goods references remain outstanding;
training eligibility is false. No calibrated sensor noise or scene diversity is claimed.
See docs/sensor_condition_generation.txt and docs/sensor_condition_evidence.json.

Benchmark preparation qualification
The goods task definition, corrected-target importer and source-bound admission
workflow are verified. The 36-frame native candidate workspace includes all pilot
sources. Dataset acceptance is in progress; the qualified reference and eligible
variant counts remain zero. The GPU runtime passed a discarded fixture update and
strict checkpoint reload at the configured training resolution and batch size.
This verifies preparation and runtime compatibility; no goods benchmark result or
synthetic-data improvement is claimed. See docs/preparation_readiness.txt and
docs/preparation_readiness.json for the current qualification evidence.
