DubaiDATA preparation and benchmark readiness

Engineering qualification
Dataset preparation, controlled real-sample synthesis, source-bound reference import
and dataset admission are implemented and verified. Customer-specific task rules are
isolated in the goods task adapter. Existing source data, caches, historical evidence
and research checkpoints are preserved.

Implemented interfaces
- Native reference preparation with deterministic training/development selection.
- Task definitions for foreground, background, uncertainty and 0/1/255 target IDs.
- Source-bound corrected-mask import with native geometry and lossless export checks.
- Acceptance records bound to the exact generated batch snapshot.
- Admission requiring condition acceptance, corrected source targets, matching
  task versions, provenance, split membership and reference coverage.
- Separate qualified target fields; original semantic predictions retain their origin.
- Foreground metrics that exclude ignored pixels and expose undefined denominators.

Verified evidence
115 contract and integration tests passed. Editor interaction, confirmation reset,
RLE export/import, stale bindings, malformed masks and invalid admission paths are
covered. The distribution includes the editor template and qualification workers.
The native workspace contains 24 training and 12 development candidates, including
all six condition-pilot sources. All 108 source files were verified unchanged;
no held-out test sensor payloads were opened. Thirteen historical depth checkpoints
retain their original checksums.

Benchmark configuration and runtime
The goods comparison configuration declares inputs, preprocessing, initialization,
loss, optimizer, model seeds, selection metrics and matched update budgets.
A discarded fixture optimizer step passed on the local GPU at 640x360, batch size 4,
float32. Strict checkpoint reload and native-resolution logits passed. Peak CUDA
allocation was approximately 1.15 GiB; reserved memory was approximately 1.37 GiB,
including the reload check. This is a runtime observation, not a full-run memory bound.

Dataset qualification status
The original preparation evidence is preserved in docs/preparation_readiness.json.
The current reference cohort contains 30 training and 12 development samples with
saved source-bound review provenance. The bounded RGB-condition experiment is
recorded in docs/goods_benchmark_status.txt; its candidate was rejected for recall
regression. Scene appearance qualification and scene-data admission remain pending.

Capability boundaries
Reference validation, sensor/scene fidelity, matched utility comparisons and final
held-out evaluation have separate acceptance criteria. Runtime fixtures establish
interface correctness rather than task accuracy. Model-assisted references can
retain anchoring bias; these pilot counts do not establish statistical adequacy.
Fusion and unsupported sensor generation retain their existing restrictions.
