Pipeline organization and research environment
Scope
Preparation, training, prediction and audit workflows are integrated as reusable
project modules with explicit inputs and output locations. This integration
record covers the depth-research workflow; it does not establish goods accuracy,
synthetic-data realism or production sensor-fusion readiness.

Completed
- Ten legacy scripts integrated under src/ingestion, src/training, src/inference
  and src/validation with professional purpose-based names.
- Project-package imports and direct-file bootstraps work from another cwd.
  No imported audit performs dataset/model reads or report writes.
- Explicit CLI paths replace workspace-specific defaults. Quality warm-start
  root is configurable. Outputs cannot overwrite raw/input sources; prediction
  paths must explicitly end in .npz. Existing results require intentional reuse.
- Reused byte-identical train/development caches at 160x90 and 320x180, and 13
  existing checkpoints, inside ignored data/caches and models directories.
- Recorded exact checkpoint hashes, architecture/resolution and gate state in
  configs/checkpoint_registry.json. No historical weights or result hashes rewritten.
- Added ignored local .tools/training_runtime.json and pinned requirement files.

Verified
- 55 unit/contract tests passed, including eight migration-specific tests.
- All ten CLIs passed --help from outside the project directory.
- All 13 checkpoints loaded strictly and produced finite native-model CUDA outputs.
- Three isolated optimizer steps passed; temporary weights were discarded.
- Both prediction CLIs ran on a training frame. Quality inference preserves
  observed depth. Inferred original-invalid regions remain unvalidated.
- Preparation decoded two June frames and passed lossless cache round-trips;
  the October record was read only as split metadata, not sensor pixels.
- Integrated stress audit passed 30 paired examples, native RGB byte identity,
  lossless PNG, clean observations, invalid-target masking and training-only donors.
- Eighteen original model/preprocessing components retain identical executable AST.
  Full retraining was unnecessary and was not performed. All original artifacts
  and checkpoint copies remain unchanged. No October model evaluation occurred.

Training environment
Python 3.12.15; torch 2.9.1+cu128; torchvision 0.24.1+cu128; CUDA runtime 12.8.
NumPy 2.5.3; Pillow 12.3.0; SciPy 1.18.1; Matplotlib 3.11.2.
GPU: NVIDIA GeForce RTX 5070 Laptop GPU; actual CUDA matrix kernel passed.
The existing verified environment is reused, avoiding another large installation.
The exact executable path is machine-local in .tools/training_runtime.json.
The ingestion-only .venv is not assumed to contain the CUDA training packages.

Execution contract
Use the interpreter recorded in the ignored local runtime configuration. Select
fresh output locations and preserve raw inputs and existing model results.
Dependency versions describe the verified environment snapshot. Reproducible
environment specifications are retained under requirements/.

Checkpoint families
models/depth_baseline: six-channel 160x90 baseline; one original checkpoint.
models/depth_context: eight-channel 160x90 local/RGB/depth comparisons and the
  observation-preserving recommended_model.pt; eight original checkpoints.
models/depth_quality: eight-channel 320x180 depth-only candidates; four originals.
  research_candidate.pt is the preferred research export. Denoising is blocked.
These depth experiments remain separate from the chosen goods-segmentation MVP.
Low-resolution sensor-depth research does not prove goods accuracy or physical realism.

Related capabilities
The native reference and real-only training/evaluation interfaces are documented
in README.md and docs/preparation_readiness.txt. Reference qualification,
generation fidelity, controlled synthetic-data comparisons and held-out evaluation
are separate acceptance criteria. Optional fusion and extra-annotation provenance
require their own evidence.
